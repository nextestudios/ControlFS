# Changelog

English (US) release notes, mirroring CHANGELOG.md (Brazilian Portuguese). Before publishing a version, add a `## [VERSION]` section to **both** files: the release workflow uses the section matching the tag and fails if either is missing.

## [Unreleased]
### Fixes
- **The app no longer freezes after copying files:** the engine reported progress for every 80 KB block and each report redrew the screen on the UI thread; on a large copy the UI queue filled up and the app stopped responding during and right after the copy. The engine now limits its reports and the UI receives at most about 10 updates per second, always the latest one (#257).

### Improvements
- **More from the team in the main Menu** (#260): the Menu has a **Mais da equipe** entry that opens the list of the team's official apps (name, logo, what it does, platform and the button that opens the site in the browser). The catalog grows in two-column rows as the team publishes more apps, and an empty catalog shows just a notice and **Fechar**. Nothing is downloaded, installed or launched on its own.
- **Same progress for every measurable operation (#257):** copy, move (including across drives), Paste after Copy or Cut, compression, extraction (including batch extraction and inside large files), batch delete and the integrity test show the percentage, "X of Y items", "A of B MB", the speed and, when it can be computed reliably (at least 3 s of work and 5% done), "about N min remaining (estimate)". The percentage never goes backwards and time spent paused doesn't count. With no known total (for example while the folder is still being analysed, or in solid archives that don't declare sizes) only the current activity shows, with no percentage or estimate. Cut still only marks the items: progress starts when you paste. The details of an operation opened in Menu → Operations follow the progress live.

### Fixed
- **Phone pairing stuck on "Connecting to PC…" (#259):** the phone page's script is allowed by a hash in the Content-Security-Policy, and a build whose embedded page had Windows line endings (CRLF) produced a hash the browser never matched, so the browser blocked the script and the page stayed on its first text with no error. The page is now assembled with LF endings (the way browsers hash it), and a `.gitattributes` rule keeps the phone page files LF. Reproduced with the real server and WebKit (Safari's engine) and Chromium; not verified on a physical iPhone.
- **The phone page always ends in a clear state:** 12 s to open the secure channel and 10 s to verify it, then a message that tells apart "PC unreachable" (same Wi-Fi, guest networks, Firewall), "the QR code expired or was already used" (generate and scan a new one), "the PC answered but the secure check failed" and a **Try again** button while the QR code is still valid. While waiting for **Permitir** on the PC the page shows "Waiting for permission on the PC" with a countdown. A script that can't start in the browser now says so on screen.
- **The PC dialog follows the phone:** the QR code dialog shows "A phone opened the page" or why a phone that arrived was refused or failed the check (short reason code), and the local log (`startup.log`) records refusals with reason codes only (never keys, addresses of the QR code or content).

## [0.11.1-alpha.1]
### Performance
- **Lower memory at rest:** two seconds after the first frame, with "Light in the background" on (the default), ControlFS returns what startup left over to Windows once (one compacting garbage collection and a working-set trim). In the CI measurement the working set at idle went from ~152 MB to ~18 MB and private bytes from ~60 MB to ~56 MB; pages the app uses come back on demand.
- **Faster folder open:** sorting names no longer asks Windows to compare each letter (a 5,000-file folder sorted in ~35 ms, now ~15 ms in the CI measurement). The startup log also records where the time goes (controller start phases, memory after the first frame, and how long each folder takes to list, sort and draw).
- **Less background work at startup:** the .NET runtime no longer starts a background garbage-collection thread and no longer instruments the first calls for profile-guided optimization (one thread and a little memory less). In side-by-side pairs measured at the same time, opening was up to 250–350 ms shorter, but the gain did not repeat in later measurements, so we don't promise it: nothing measured got worse.

### Known limitations
- Not yet validated with physical controllers (issue #78: Menu → Teste de controles…).
- Executables are not code-signed yet (#84, SignPath Foundation application under review): SmartScreen may warn on first run.
- Opening takes about 1 s (.NET and the Windows App SDK start before the app); see why in the README.

## [0.10.0-alpha.1]
### Performance
- **Light in the background (to game with ControlFS open):** with the window minimized or behind a game, ControlFS drops to below-normal priority and Windows 11 efficiency mode, reads controllers only to notice connections (once per second, without queuing the buttons and sticks the game is using), stops polling drives and, after 5 seconds, gives the memory it isn't using back to Windows (in the Smoke run: from ~153 MB to ~18 MB working set). CPU while minimized: from ~1.4–2% to ~0.5% of one core. Coming back to the window restores everything at once; copies and extractions keep running (slower) and playing audio or video keeps normal priority. Menu → Configurações → **Leve em segundo plano** (on by default).
- **Lighter idle:** with no controller connected, ControlFS no longer reads SDL every 8 ms with the Windows timer at 1 ms — keyboard and mouse arrive as events and reading drops to 4 times per second, only to notice a controller arriving (fast reading comes back as soon as it connects). Idle CPU with the window in front: from ~1.5% to ~0.5% of one core.
- **Startup:** the automatic update check starts after the first frame, and the caches for large icons (details panel, Home cards) keep fewer images. The Smoke workflow now measures time to first frame, memory, CPU and threads (active and minimized) and package sizes; numbers and decisions (ReadyToRun and portable compression) in `docs/performance.md`.

### Improvements
- **Legibility and handheld density:** context texts that were 14 px — the line above the list (archive, Git, search), "PAINEL ESQUERDO · ATIVO" (left pane · active) in two-pane mode and the inactive pane — are now body size, and on handhelds no informational text is below 16 px. In the folder picker that line becomes the screen title ("Copiar para… · escolha a pasta"). At 720p/800p comfortable rows are ~64 px (was 88: only ~5 fit) and the first launch on a handheld starts in the compact list, never changing a saved choice; the bottom bar no longer wraps (the less essential prompts are left out; Abrir, Voltar, Ações and Menu stay) and the path root ("Meu computador") no longer disappears with large text. Long paths in the details panel lose the middle, not the end ("C:\…\2026\Relatórios trimestrais"), and the main folder cards don't repeat the path on a 4K TV. The on-screen keyboard starts on the first letter, only the focused key has an outline (Done stands out by its text color) and handhelds show only the essential prompts. In the light theme the logo uses a version with a dark name (no dark plate behind it) and keys stand out from the panel (contrast checked by tests).
- **Notices that don't push the list, no dialog after a clean operation, visible progress:** transient notices ("Exibição em grade.", "Lista compacta.", why an option is unavailable) show as a pop-up in the bottom-right corner at body text size and fade after about 3 seconds; the bottom bar no longer changes height (it used to grow up to 124 px and shrink the list). The notice never covers the focused item (it moves to the top corner when needed) and is read by Narrator. A copy, move or delete without any problem no longer opens a dialog you have to close: the notice says "3 itens copiados · Menu → Desfazer" (3 items copied · Menu → Undo); warnings, failures and cancels still open the result, which also stays in Menu → Operações. While anything runs, a thin bar under the title strip shows the overall progress and the strip shows the percentage; Menu → **Operações** splits **Em andamento** (in progress: state icon, percentage and items, updating while the menu is open) from **Histórico** (history). The search summary and the count of items without permission move to the line above the list.
- **Search from home:** **Select/View** on the home screen searches the main folders (Downloads, Documents, Desktop, Pictures, Videos, Music) with the same engine as a folder search (never follows links; East/B cancels; Back returns home). In This PC, search looks in the focused drive.
- **Empty lists with a next step:** "Lixeira vazia" (Recycle Bin empty), "Compactado vazio" (empty archive), "Pasta vazia — Y Ações: Colar / Nova pasta" (empty folder — paste / new folder; paste only when something is copied) and, for a search with no results, the filters and a new search, with the active controller's buttons.
- **Readable errors:** Windows errors become a plain message with what to do (not found, access denied, in use by another program, disk full, path too long, device not ready) instead of "Erro inesperado: IOException" or the system's raw text. The original text stays under "Detalhes técnicos" (technical details) and in the local log.
- **Theme-colored title bar and full screen** (#230): the white minimize/maximize/close bar is gone — like Discord, the top of the window uses the theme background (dark or light, updating live) with the ControlFS logo, and the three Windows buttons use the theme colors (close still turns red on hover; with high contrast, the system colors). Dragging by the top, double-click to maximize and Windows 11 snap layouts keep working. Next to minimize there is a **full screen** button; also **F11**, Menu → **Tela cheia** (tile) and Menu → Configurações → **Tela cheia**. The choice is saved and applies the next time you open ControlFS; videos still go full screen on their own and, when closed, the window returns to what you had chosen. The real caption button colors haven't been checked on every Windows version yet (see `docs/TESTING.md`).
- **Welcome and guided tutorial** (#231): the first time ControlFS opens, five full-screen steps, all driven by the controller: welcome; how the controller works (the buttons **of the controller in use** — Open, Back, Actions, Menu, Search, Mark, L1/R1 for the top bar, L2/R2 for tabs, R3 for the view; Actions changes with the context); the basics with immediate effect (confirm with the bottom or right button, button labels, theme, list/grid, Fluidez); privacy (everything stays local, the update check is optional, the phone link is off until you open it); and the invitation **Quer fazer o tutorial guiado?** (**Começar tutorial** / **Agora não**). The **D-pad** moves, **South** chooses, **East** goes back a step, **Start** skips everything without asking; keyboard and mouse work too and Narrator reads each step. The **guided tutorial** uses the real screen: it highlights the region (list, top bar or footer), shows the exact button of your controller and only advances once you do the step — move the focus, open a folder, go back, open and close Actions, the top bar with L1/R1 and a shortcut, list/grid with R3, search, and the Menu with Configurações. No step changes files. **Mark** opens the tutorial options (continue, **Voltar passo** (previous step), **Pular tutorial** (skip)); with the mouse, the callout's buttons. It ends on Home with the first card focused. To see it again: Menu → **Ajuda e tutorial…** (guided tutorial, welcome again, About) or Configurações → **Rever boas-vindas**. People who already used ControlFS don't get the welcome on their own.
- **Phone as a controller** (#223): Menu → **Conectar celular…** (connect phone) shows a QR code. Point the phone's camera at it (Android or iPhone, on the same Wi-Fi/wired network as the PC) and a page opens in the browser, with no app to install and no cloud: D-pad, a swipe area to scroll, **Abrir** (open), **Voltar** (back), **Marcar** (mark), **Ações** (actions), **Menu**, **Buscar** (search), **Lista/Grade** (list/grid), regions and pages, plus a field that uses the phone's keyboard to type into the field open in ControlFS. The PC shows the phone's IP and a 6-digit code the phone also shows; the phone only takes control after **Permitir** (allow) on the PC. The QR code is valid for 2 minutes and for one connection; the link is local and encrypted (AES-256-GCM, a fresh key per pairing that never travels over the network). Important confirmations (delete, replace, undo) stay PC-only — from the phone, only Back works. Menu → **Desconectar celular** (disconnect phone), or Disconnect on the phone, ends it; closing the page, losing the network or closing ControlFS does too, and reconnecting needs a new QR code. The first time, Windows Firewall may ask: allow it on private networks. Not yet validated with real phones (see `docs/TESTING.md`).
- **Settings in grids** (#227): in each group of Configurações, short settings (view, density, details panel, theme, accent color, sort, hidden items, search in subfolders, recents, restore tabs, suggestions, confirm button, button labels, Fluidez) are now tiles with an icon, a name and the current value; settings with long descriptions or that open another screen stay in a list. The controller moves in 2D between the grids and the lists.

## [0.9.0-alpha.1]
### Improvements
- **Two panes** (#56): Menu → **Dois painéis** shows two folders side by side, each with its own location, history, marks and focus. The active pane has a cyan outline and the "ATIVO" (active) title; **L3** (press the left stick; **Tab** on the keyboard) or a click switches panes without touching marks. In Actions, **Copiar/Mover para o outro painel** (copy/move to the other pane, quick tiles) and **Extrair para o outro painel** (extract to the other pane) show the source and destination before running, and the other pane refreshes when done. Handhelds and narrow windows keep a single pane.
- **Edit text from the preview** (#62): in the preview of a text file (up to 1 MB, fully shown), **North** starts editing. The focused line is highlighted; **Up/Down** pick the line, **South** opens it on the on-screen keyboard, **North** inserts a line above/below, deletes the line or undoes, **Start** saves. Saving asks first and swaps the file in one step (never half-written), keeping the encoding, BOM and line endings; the original stays next to it as `name.controlfs.bak`. **Back** with changes asks before discarding, starting on "Continuar editando" (keep editing). If another program changed the file while you were editing, saving warns before replacing it. Binary, read-only, oversized files or encodings that wouldn't round-trip are refused with the reason.
- **Full-screen video player** (#61, #170): **South** on an MP4, M4V, MOV, WMV, AVI, MKV, WebM or 3GP file (from the list or the grid; North → **Assistir aqui** too) plays it across the whole window. An overlay with the title, elapsed/remaining time, progress bar, volume, subtitles and audio track shows up on any button and fades after 3 s of playback. **South** pauses/resumes; **Left/Right** (±10 s), **LB/RB** (±1 min) and **LT/RT** (5% of the video) show the target in large type and on the bar before jumping (South jumps right away, Back cancels); **Up/Down** change the volume; **North** opens subtitles (embedded, or an `.srt`/`.vtt` with the same name next to the video), audio track, mute, start over and "forget where I stopped" — whatever the video lacks is disabled with the reason. **Back** first hides the overlay, then returns to the list with the focus on the video. A partly watched video asks **Continuar de 12:34** (resume) or **Começar do início** (start over) — only for the same file: another file with the same name, or the same one edited, doesn't inherit the position; Configurações → **Apagar onde os vídeos pararam** erases them all. Windows codecs only: a format without a codec shows a clear message and Back leaves.
- **Create 7z** (#67): in **Compactar…** (Compress), **Formato** now cycles ZIP → TAR.GZ → **7z** (solid LZMA, smaller than ZIP; opens in 7-Zip and in the current Windows 11 File Explorer). Same rules as before: links aren't followed, the archive only appears when finished and nothing is overwritten. No new dependency: it uses the LZMA encoder already shipped in SharpCompress.
- **Network locations** (#27): network drives mapped in Windows and the **Network locations** shortcuts (File Explorer → "Add a network location") show on Home and in Meu computador (This PC) with the network symbol and the share (e.g. "filmes (Z:)", "Rede · \\nas\filmes"); South opens and browses them like any folder. A drive Windows remembers but isn't connected shows as "desconectada" (disconnected), never as an error. ControlFS doesn't contact servers to build Home (a NAS that is off no longer holds up startup or going back Home) and stores no credentials: it only uses what Windows already knows.
- **Audio playback** (#60): **South** on an MP3, WAV, WMA, M4A, AAC, FLAC, OGG or Opus file plays it inside ControlFS (North → **Ouvir aqui** too). **South** pauses/resumes (at the end, it starts over), **Left/Right** skip back/forward 10 s, **LB/RB** 1 minute, **Up/Down** change the volume and **North** mutes/unmutes; the panel shows the state, time, progress bar and volume. **East/B** closes and the sound stops right away. Only Windows codecs are used: a format without a codec shows a clear message.
- **Light theme and accent color** (#37): Menu → Configurações → **Tema** (automatic, which follows Windows' app mode and changes with it; dark; light) and **Cor de destaque** (cyan, blue, green, amber, magenta, orange). Changes apply at once to every screen, menu and the on-screen keyboard, and are saved. Every combination is contrast-checked by tests (text ≥ 4.5:1; focus ring ≥ 3:1). **Change:** if Windows is in light mode you now get the light theme; Configurações → Tema: escuro brings back the previous look.
- **PDF preview** (#59): **South** on a `.pdf` shows its pages inside ControlFS, without Edge (North → **Visualizar PDF** too; **Open with the default app** is still there). **Left/Right** or **LB/RB** change pages, **RT/LT** zoom, while zoomed the D-pad moves around the page and **South** fits it back; **East/B** closes with the focus on the PDF. The header shows "página N de M" (page N of M). A password-protected PDF asks for the password on the on-screen keyboard (masked, never stored) and lets you try again. Pages are drawn by Windows in the background; links, attachments and forms never open.
- **Experimental: gyro aiming on the on-screen keyboard** (#77): Menu → Configurações → **Mira por giroscópio no teclado** (off by default). With a controller that has a gyroscope (DualSense, DualShock 4, Switch Pro…), turning or tilting the controller points at keys; South types, the D-pad keeps working and R3 recenters. The sensor is only turned on while the setting is on. Not yet validated on hardware; findings in `docs/decisions/0007`.
- **Split archives** (#65): `.7z.001`, `.zip.001`, `.part1.rar`, `.rar` + `.r00` and `.z01` + `.zip` open and extract from any volume. If a volume is missing, nothing is extracted and the message names the missing volumes (including the last one, when the format tells). Marking several volumes of the same set for a batch extraction counts as one archive. Split TAR/TAR.GZ is refused instead of being half-extracted.
- **More visible image preview controls** (#171): the panel only shows what works right now (no "Anterior" on the first image, no "Próxima" on the last; "Ajustar à tela" only while zoomed), with the buttons of the controller in use. After 4 s without input the prompts fade (Close stays highlighted) and the header says "qualquer botão mostra os comandos" (any button shows the controls); any button brings them back and still does its job. The footer keeps its size, so the image never jumps.
- **Restored tabs** (#51): with two or more tabs open, ControlFS reopens the same folders, in the same order and on the tab that was active. A folder that is gone (or a disconnected drive) becomes an "(indisponível)" (unavailable) tab that shows Home with a notice, without holding up startup. Menu → Configurações → **Restaurar abas ao abrir** (restore tabs on launch) turns it off.
- **Reopen closed tab** (#52): Menu → **Reabrir aba fechada** (also in Menu → Abas and North on the tab strip) brings back the last closed tab at the same position, with its folder and history (Back/Forward); marks don't come back. The last 10 tabs closed in this session are kept.
- **Duplicate tab** (#53): North on the tab strip (or Menu → Abas) → **Duplicar aba** opens, right next to it, a tab at the same folder (or archive), focused on the same item, with a copy of the history that then goes its own way; marks stay only in the original tab.
- **Maximum smoothness** (default): while the window is active, the controller is read ~125 times per second (every 8 ms, with the Windows clock at 1 ms), enough for 120 Hz screens — Windows used to round it to ~64. Drawing still follows the display's rate. Menu → Configurações → **Fluidez** switches to **battery saver** (handhelds).
- **Smaller menus with a quick-action grid** (#193): item actions (North) and the Menu (Start) open with the most used actions as tiles at the top — icon with a short label underneath, readable from a distance (e.g. Abrir, Recortar, Copiar, Colar, Renomear, Propriedades and, last and in red, Excluir). The rest follows in a compact list, with the explanation only on the focused option. In the grid, Left/Right move between tiles, Down goes into the list and Up returns to the tile you came from; the initial focus is never a destructive action, Narrator says "ação rápida N de M" (quick action N of M) and clicking a tile chooses it. Every menu is narrower and shorter.
- **Configurações (settings)** (#193): settings moved out of the Menu into Menu → **Configurações**, grouped (Exibição, Busca e privacidade, Controles, ControlFS). Changing a setting keeps the screen open with the new value; Back closes it. Nothing was removed: view, density, details panel, sort, hidden items, search in subfolders, recents, keyboard suggestions, confirm button, button labels, Fluidez, active controller, controller test, controllers without a profile and updates are all there.
- **Right-stick scrolling** (#175): tilting the right stick scrolls whatever is active — list and grid (one row per step; the focus follows and stays visible, never wrapping at the ends), menus, the text preview (lines and, sideways, columns), a zoomed image and the body of long dialogs and About — without moving anything behind it. A short flick scrolls one step; the further you tilt, the faster it goes, and holding it accelerates gradually; letting go stops at once. A deadzone with hysteresis prevents drift; pressing the stick (R3, list ↔ grid) doesn't scroll, and an idle controller never takes over from the active one. The D-pad and left stick behave as before.
- **Batch rename** (#71): with marked items, North → **Renomear em lote…** offers numbering (`Photo 001.jpg`…), find and replace (with an optional match case), prefix and suffix, and upper/lower/title case, with a live preview of current name → new name. Extensions never change; invalid names, names repeated in the batch or already used in the folder block the batch with the reason before touching the disk. **Start** applies it through the Operations center with per-item results, and Menu → **Undo** puts every name back.
- **Disk usage analysis** (#72): North on a folder or drive → **Analisar uso do disco** shows the folders and files that take the most space, biggest first, with each one's share. South drills into a folder (without reading the disk again), East goes back up, and a file opens its folder with it focused. The scan runs in the background, East cancels at once, junctions and links are never followed and the totals match Explorer's Size.
- **Mount and unmount disk images** (#73, #74): North on an `.iso`, `.img`, `.vhd` or `.vhdx` → **Montar imagem** uses Windows' native mounting (the same as Explorer, no drivers or command line) and opens the new drive; ISO/IMG are read-only. North on a drive that is a mounted image (by ControlFS or Windows), in This PC or on the home screen → **Desmontar imagem…**, with a confirmation that starts on Cancel. Errors are explained.
- **Git status** (#75): optional (Configurações → Exibição → **Status do Git**, off by default). In repository folders, the top line shows the branch and how many items changed, and items show "Git: modificado" (modified), "novo (não rastreado)" (untracked), "adicionado" (added), "conflito" (conflict) or, for folders, "com mudanças" (has changes). Read-only, no Git installation needed and nothing from the repository is ever executed (libgit2); browsing never waits for the status.
- **Open terminal here** (#76): North → **Abrir terminal aqui…** opens Windows Terminal (or PowerShell) in the current folder after a notice that starts on Cancel (the terminal is outside ControlFS and doesn't work with the controller); an option also opens Windows' on-screen keyboard. Nothing is executed: the folder is only the working directory, never part of a command line.

### Security
- Text editing: only files that round-trip byte for byte (same encoding, BOM and line endings); written to a registered temporary in the same folder, flushed to disk and swapped in one step (`File.Replace`, which keeps attributes and permissions) with a copy of the original; never edits binaries, files over 1 MB or read-only files.
- Video: handed to the Windows player as a local stream (never a URL) after refusing disguised executables; external subtitles only as ordinary local files up to 5 MB (no links); the saved position is only a SHA-256 digest and seconds.
- Audio: the file reaches the Windows player as a local stream (never as a URL, no network), after checking it isn't a disguised executable; closing releases the file.
- **Update key rotation** (#86): the app accepts manifests signed by any key in its trusted set, so the signing key can be rotated (or a backup key used if the current one is lost) without breaking automatic updates. A copy that doesn't know the new key yet first updates to the transition release that carries it; other keys are still refused and there is never a downgrade. Procedure in `docs/decisions/0006`.
### Fixes
- 7z archives with empty files no longer ask for a password for nothing: the engine flagged empty files as protected. (#67)
- 7z archives whose file list is password-protected: a wrong password now says "Senha incorreta" (wrong password) and asks again, instead of reporting a corrupt archive. RAR5 and 7z with encrypted headers are now validated with fixtures: without the password not even the names show; with the right one they list and extract. (#70)
- Menus no longer open focused on an unavailable option (e.g. Paste with nothing copied), and the quick-action tiles all have the same width.
- Menus, confirmations and the on-screen keyboard are now smooth: moving the focus only changes the options/keys that gain or lose it, instead of rebuilding the panel, shadow and scroll area on every move (which left a "ghost" and a scroll jump).
- The row that just lost focus no longer keeps a grey "ghost" highlight when the mouse pointer rests over the list or grid: only the focused item has the ring; marked and cut items keep their own marks. (#182)
- The ControlFS icon no longer sits on a black square: the executable, window, taskbar, Start menu, shortcuts and installer use the artwork with a transparent background and the neon glow, at every Windows size (16–256 px). If Windows still shows the old icon, that's its icon cache. (#187)
### Security

- The 0.1.0-alpha.3 portable `ControlFS-Portable-x64.exe` closed on startup: it looked for its resource file by the executable's name. The file is now `resources.pri` and is found under any name. (#4)
- CI now opens the portable under its exact published name (it used to be renamed, which hid the bug). (#4)


## [0.1.0-alpha.3]
### Fixes
- The app closed right after opening (installed and portable) in 0.1.0-alpha.1 and 0.1.0-alpha.2: the app resource file (`ControlFS.pri`) was missing and WinUI couldn't find its styles. Fixed.

### What's new
- Single-file portable version, `ControlFS-Portable-x64.exe`: keeps settings and logs in the `ControlFS_Data` folder next to it (if that folder isn't writable, it uses `%LOCALAPPDATA%\ControlFS` and tells you).
- Local startup and crash log in `logs` inside the data folder, to diagnose problems (no passwords or file contents).
- Every release is now published only after CI actually opens the portable and the installed app on Windows and confirms the window shows up.

### Updating
- From 0.1.0-alpha.1 or 0.1.0-alpha.2: those versions didn't open, so they can't update themselves. Download and run `ControlFS-Setup-x64.exe` once.


## [0.1.0-alpha.2]
### What's new
- Windows installer (`ControlFS-Setup-x64.exe`): per-user install, no admin, Start menu shortcut and an optional desktop shortcut.
- Automatic updates in the installed version: the app checks once a day, downloads in the background and offers "Install and restart"; if you postpone, it installs when you quit. All of it can be turned off in Menu → Updates.
- Verified updates: the app only accepts an installer whose manifest is signed with the project key and whose SHA-256 and size match; same or older versions are refused.
- The portable version tells you when a new version exists (replacing it is manual).

### Fixes
- `SHA256SUMS.txt` now uses LF line endings, so `sha256sum -c` works on Linux and macOS.

### Updating from 0.1.0-alpha.1
- 0.1.0-alpha.1 had no updater: download and run `ControlFS-Setup-x64.exe` once. Updates are automatic from then on.


## [0.1.0-alpha.1]
### What's new
- First public release (pre-alpha): a controller-first file manager with a built-in ZIP extractor.
- Browse known folders (through the Windows API) and drives, with history, sorting, hidden items, marking and properties.
- Own on-screen keyboard (Portuguese/English, accents, symbols, cursor, masked passwords) usable with only directions, confirm and back.
- Create folders with Windows naming rules.
- ZIP: browse without extracting, extract all or a selection (dedicated folder, here, or "to…" with an in-app folder picker), ZipCrypto passwords, conflicts, progress and per-item results.
- Safe extraction: path containment, blocked links, refused name collisions, limits, staging and CRC checks.
- SDL3 input mapped by physical position with a switchable confirm/back convention; keyboard and mouse use the same model.

### Known limitations
- Not validated on Windows with physical controllers yet; not code-signed.
- ZIP only (no AES or ZIP64 yet). Copy, move, rename, delete, search and two panes don't exist yet.
